# إعداد طرق الدفع التجريبية

تستخدم شاشة طرق الدفع رمز Moyasar قابلًا لإعادة الاستخدام، وتخزن بيانات البطاقة المقنّعة فقط. لا يدخل رقم البطاقة أو CVV إلى خادم فزعة أو قاعدة بياناته.

## المتطلبات

- مشروع Supabase مع تفعيل تسجيل الدخول برمز SMS والسماح بإنشاء الحسابات وإعداد مزود إرسال الرسائل.
- مفاتيح Moyasar التجريبية `pk_test_...` و`sk_test_...`.
- نشر ترحيل قاعدة البيانات ودالة Edge الموضحة أدناه.
- يجب أن يعمل الموقع عبر HTTPS عند الاختبار المنشور. يستخدم التحقق البنكي تدفق 3-D Secure لدى Moyasar.

## إعداد التطبيق

1. انسخ `.env.example` إلى `.env.local` وأدخل عنوان Supabase ومفتاح `anon` ومفتاح Moyasar العام التجريبي فقط.
2. لا تضع `sk_test_...` أو مفتاح `service_role` في أي متغير يبدأ بـ `VITE_` أو في ملفات التطبيق.
3. طبّق ترحيل قاعدة البيانات:

   ```sh
   supabase db push
   ```

4. اضبط أسرار دالة Supabase من بيئتك الآمنة:

   ```sh
   supabase secrets set SUPABASE_URL="..." SUPABASE_ANON_KEY="..." SUPABASE_SERVICE_ROLE_KEY="..." MOYASAR_SECRET_KEY="sk_test_..."
   ```

5. انشر الدالة:

   ```sh
   supabase functions deploy payment-methods
   ```

6. اضبط عنوان إعادة التوجيه `/payment-methods` في إعدادات Auth في Supabase، وأضف النطاق المحلي/المنشور إلى عناوين Redirect المسموح بها.
7. في Sandbox فقط، استخدم بطاقة من [قائمة اختبار Moyasar الرسمية](https://docs.moyasar.com/guides/card-payments/test-cards) وأكمل تحقق 3-D Secure. لا تستخدم أرقام بطاقات حقيقية.

## حدود التكامل

- تستخدم إضافة البطاقة واجهة [Moyasar Tokenization API](https://docs.moyasar.com/guides/tokenization/create-token) الرسمية من المتصفح بمفتاح النشر فقط؛ Moyasar.js مخصص لنموذج الدفع، ولا يوفر تدفق حفظ بطاقة بلا عملية دفع. لا ترسل الواجهة PAN أو CVV إلى خادم فزعة.
- تسجيل الدخول المحلي القديم في فزعة لا يعدّ مصادقة؛ تستخدم هذه الصفحة تحقق SMS من Supabase مستقلاً، ويجب تهيئة مزود الرسائل قبل الاختبار.
- تدفق Moyasar الرسمي لإضافة بطاقة دون شراء ينشئ تفويض تحقق بقيمة 1 ريال يتم إلغاؤه تلقائيًا بعد التحقق؛ لا يُحصّل كمبلغ شراء.
- يدعم حفظ البطاقات مدى وVisa وMastercard. Apple Pay مرتبط بجهاز Apple وتاجر/نطاق معتمد، ولا يمكن حفظه من شاشة إدارة البطاقات دون عملية دفع؛ يعرض كطريقة دفع عند تجهيز صفحة الدفع الفعلية فقط.
- ما زالت صفحة الدفع/السلة غير موجودة في التطبيق. هذه الإضافة تدير رموز البطاقات ولا تنشئ طلبًا أو تخصم مبلغ طلب. قبل إطلاق الدفع التجاري، يجب إنشاء تدفق checkout يحدد المبلغ من الخادم، وينشئ/يتحقق من الدفع لدى Moyasar، ويحدّث حالة الطلب بعد التحقق server-to-server.
- إبقاء `MOYASAR_SECRET_KEY` على دالة Supabase وحدها، وتفعيل نطاقات Auth المسموحة وتحديد رسائل OTP قبل نشر التطبيق.
